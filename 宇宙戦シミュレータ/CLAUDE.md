# 宇宙戦シミュレータ（Claude Code 向けの作業メモ）

ユーザーの個人的な思考実験（人類統合機構と異星勢力ザイレンの宇宙戦争）の会戦を計算するツール。会話は日本語。作業の途中経過の説明やコマンドの説明（description）も日本語で書く（英語だと細かいニュアンスが伝わらない）。

## ここでやること

ユーザーはここで「戦闘結果をいろいろいじる」。艦の性能・配置・行動・陣営の設定を変えて、勝敗や損害がどう変わるかを調べる。頼まれたら、まずコマンドで戦闘を回して数字を出し、結果を表で返す。

```
node tools/battle.js sB                                   # プリセットを20回戦わせて勝率と損害
node tools/battle.js sB --set types.quiet.shield=6000     # 値を書き換えて回す
node tools/battle.js basic --seed 3 --events              # 1回分の経過を時刻順に
node tools/sweep.js sB --param types.quiet.shield --values 2500,4000,6000,8000   # 値を振って比べる
node tools/battle.js sB --set ... --save scenarios/試し.json                      # 変えたシナリオを保存
node test/run.js                                          # エンジンのテスト
```

- プリセット名: `basic`（正面衝突）、`sA`（S星系外縁 A）、`sB`（S星系外縁 B）、`grand`（大規模会戦: S星系決戦。約400隻で1回5秒ほどかかる）、`arms`（副兵装の試し撃ち）、`giant`（巨大艦の試し。ザイレンの旗艦）、`lan`（同性能の数の差）、`empty`。`scenarios/*.json` も同じ中身
- 大規模会戦の兵力は `presets.js` の `grandBattle(o)` の引数で変えられる（`P.builders.grandBattle({ w2: 90 })` のように Node から呼べる）
- `--set` と JSON は**内部の単位**: 時間は秒、距離は光秒、速さは c、割合は 0〜1。画面では分や % で見せているので換算する（45分 → 2700、30% → 0.3）
- 艦をまとめて変えるときは `"units[type=narm,side=1].ai=hold"` のように条件で選ぶ（`[3]` は4番目、`[*]` は全部）
- 艦の追加・削除や配置の変更は、シナリオの JSON を書き換えるか、Node のスクリプトで `presets.js` の `formation()` を使う
- 形式の全体は `シナリオ形式.md`、計算のしくみは `README.md`、画面の操作は `操作方法.md`

## 結果を報告するとき

- 何回（どのシード）回したか、何をどう変えたかを必ず書く。1回だけの結果で結論を出さない（命中判定と到着誤差が乱数で変わる）。目安は20回以上
- 勝率だけでなく、平均決着時刻・残存戦力・艦種ごとの損失も見る。時間切れ判定（`reason: time`）で決まった勝ちは、決着がついていないことに注意
- ユーザーが画面で見られるように、変えたシナリオは `--save` で JSON に書き出し、場所を伝える（画面の「保存・読込」→「ファイルを開く」で読める）

## 3Dビューア

- `viewer3d.html` / `viewer3d.js` / `viewer3d-models.js` / `viewer3d-audio.js`（効果音。Web Audio で合成し、音声ファイルは使わない）。three.js 0.170 を jsdelivr からモジュールで読む（importmap）。ネット接続が必要
- 効果音は `viewer3d.js` の `updateAudio` が、前のコマから今のコマまでの射撃・弾・演出の出来事を拾って鳴らす。こちらでは音を聞けないので、変えたら試聴用の WAV を書き出して渡し、ユーザーに聞いてもらう
- 戦いは `engine.js` で計算し直して、記録フレームを再生する（シナリオとシードが同じなら2Dの画面と同じ結果）。2Dの画面からは localStorage の `uchusen-3d-handoff` で受け取る
- 高さ（3Dの y）は見た目だけ（`computeHeights`）。混んだ群れの水平の散らし（`updateSpread`）も見た目だけ。計算には影響しない
- 射撃の記録は `SHOT_W` = 12 個ずつ（位置・命中・陣営・時刻・撃った艦・標的・種類 `SHOT_KIND`・届くまでの秒数・爆発で沈んだ数）。シェルは命中の欄に爆発で損害を受けた数が入る。貫く線（`SHOT_KIND.lance`）は着いた位置が射程いっぱいの線の端、命中の欄が線の上で損害を受けた数。シェルと誘導弾は着弾の時刻に記録する。フレームの間の射撃もすべて次のフレームにためる。記録フレームは `FRAME_W` = 11 個ずつ（10 番目が副兵装の残弾）。無人機の位置はフレームの `drones`（`DRONE_W` = 6 個ずつ）
- 艦のモデルは、両陣営のグランドデザイン（`models/デザイン.md`。人類は「軍艦＋幽子の輪」、ザイレンは「線と体節」。2026-10-16 にユーザーと決めた）にそって `models/designs.js` で組み立て、`models/gallery.html` で GLB に書き出したもの。艦種を足したり形を変えたりするときは、このデザインと共通部品にそって作る。差し替えの手順は `models/README.md`（GLB を置いて `models/models.json` に書き、`node tools/pack-models.js`）
- こちらから見た目は確認できないので、ビューアを変えたら表示の確認をユーザーに頼む

## 守ること

- 設定資料（`参考_設定資料/`、リポジトリでは一つ上のフォルダ）が正本。書き換えない。設定で決まっている数値は、通常航行 0.05c、リンク時のロックタイム45分、通信艦の再同期15分、静穏場の展開15分・維持3時間、レーン敷設 1光分あたり40分。それ以外の数値（耐久・火力・射程・回避・コストなど）は仮置きなので、自由に変えて試してよい
- **計算のルール（`engine.js`）を変えるときは、何をどう変えるかを先にユーザーに確かめる**。数値を変えて試すだけなら確かめなくてよい
- エンジンを変えたら `node test/run.js` を通す。`README.md` の「計算のしくみ」と `index.html` の「使い方」ダイアログも合わせて直す
- `engine.js` は DOM に依存させない（Node でも動かすため）
- 艦種の項目を足すときは `engine.js` の `DEFAULT_TYPE` と `TYPE_FIELDS` の両方に足す（画面の編集欄は `TYPE_FIELDS` から作られる）
- 画面（`index.html`・`ui.js`）を変えたときは、見た目の確認をユーザーに頼む
- **兵器の仕様を決めるときは勝率を気にしない。勝率を調べたり釣り合いを取ったりするのは、ユーザーから指示があったときだけ**（ユーザーの方針）
- 釣り合いを取るよう頼まれたときは、艦の数で取る。兵器の性能（威力・射程・間隔・命中率など）は釣り合いのために変えない
- プリセットの数値を変えると、`test/run.js` の「S星系外縁 A は人類の勝ち」が落ちることがある。意図した変更ならテストもユーザーと相談して直す
- 兵装の割り振りは README の「数値について」にある（2026-10-16 にユーザーと決めた。シェルは拠点と砲撃艦だけ）
- ザイレンの旗艦（オルドラ級、`flagship`）は設定資料にない、シミュレータだけの艦種。動くハブ（`hubOn`）・方舟（`hangarOn`、積む艦は units の `aboard`）・貫く線（`sKind: 'lance'`）を1隻にまとめた（2026-10-16 にユーザーと決めた）。ほかのプリセットの艦種一覧には入れていない（艦種を足すと「火力の高い敵」などの狙い方の基準が変わり、既存の結果が動くため）

## 設定側で決まっていないこと（いじる候補）

- ザイレンの反応時間（判断の遅れ）。推奨は15分より遅い値を基本にする案。`sides.1.reaction`
- 「結論2」: レーン端末付近はザイレンに有利なので、人類は端末から数光秒以上離れて出るのが基本戦術、という案（未反映）。目標地点 `goal` を H2 から離すと試せる
- ロックタイムの数値（単艦・リンク時）は仮置き

- `tools/battle.js` `tools/sweep.js` `tools/lib.js` コマンド

- `test/run.js` エンジンのテスト
